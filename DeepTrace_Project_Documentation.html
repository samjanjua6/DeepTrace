01 Executive Summary & Problem Domain

1.1 The Epidemic of Financial Instrument Forgery

In contemporary commercial banking, mortgage processing, trade credit, and retail underwriting, the verified authenticity of supporting financial documentation—primarily bank account statements, salary slips, tax challans (FBR IT-1/CPR), and utility certificates—represents the first line of defense against insolvency and fraud. However, modern digital tools have radically democratized sophisticated tampering techniques.

Borrowers and organized syndicates routinely alter closing balances, inject fictitious salary deposits, forge bank branch rubber stamps, replace account holder identities, and generate synthetic PDF statements using headless rendering engines (e.g., Puppeteer, wkhtmltopdf) that mimic legitimate banking layouts. Standard Optical Character Recognition (OCR) systems are structurally incapable of detecting these attacks because they only extract text strings without analyzing underlying typographic physics, compression artifacts, or balance continuity.

The Core Banking Vulnerability in Pakistan
In Pakistan, where over 33 commercial and microfinance banks process millions of loan underwriting files annually, manual verification teams rely on visual sampling. Financial institutions experience billions of rupees in non-performing loans (NPLs) traceably rooted in forged income documentation submitted during initial credit appraisal.

03 The 8-Stage Forensic Pipeline

3.1 Sequential Forensic Execution Model

When a document is intake-verified, it enters DeepTrace’s 8-stage pipeline. Each stage is an isolated deterministic or probabilistic analyzer that emits standardized evidence manifests and visual bounding boxes.

Stage 1: Cryptographic Custody Lock ~35 ms
Computes SHA-256 and SHA-512 cryptographic digests immediately upon byte ingress. Generates an RFC 3161-compliant trusted timestamp token. Any subsequent byte tampering invalidates chain-of-custody under ETO 2002 §30.
Stage 2: PDF Structure & Revision Forensics ~30 ms
Traverses PDF cross-reference tables (XRef), dictionary streams, and trailers. Detects multiple `/Prev` revision pointers indicating unflattened modifications, form-field text overlays (`/AcroForm`), and Producer metadata spoofing.
Stage 3: Font Typographic & Baseline Engine ~29 ms
Extracts raw glyph font descriptors (`/FontDescriptor`), encoding vectors, and bounding boxes. Computes linear regression of character baseline heights. Flags font substitution and vertical glyph jitter (> 1.2 pt variance).
Stage 4: Computer Vision & Error Level Analysis ~320 ms
Renders pages at 300 DPI. Resaves at known JPEG quality (Q = 95) and computes difference matrix D = |I - J| × 10. Isolates copy-move forgery via DCT block matching and normalized cross-correlation. Emits heatmap overlays.
Stage 5: Multi-Modal OCR & Layout Extraction ~77 ms
High-throughput OCR utilizing RapidOCR (ONNX Runtime) with Tesseract OCR fallback (supporting English and Urdu scripts). Reconstructs 2D tabular spatial hierarchies and associates extracted words with exact page coordinates.
Stage 6: Deterministic Financial Reconciler ~82 ms
Parses transactions into signed decimals. Enforces running balance continuity across Western and Pakistani Lakh/Crore formats. Validates PK-IBAN ISO 7064 MOD-97 check digits and FBR withholding tax deductions.
Stage 7: Bayesian Evidence Fusion & Risk Scoring ~59 ms
Fuses deterministic and probabilistic findings across all previous stages into a unified Bayesian belief network. Computes calibrated composite Risk Score (0–100) and assigns statutory risk tier: LOW, MODERATE, ELEVATED, HIGH, or CRITICAL.
Stage 8: Court-Admissible Dossier Generation ~117 ms
Assembles verified findings, visual proof artifacts, chain-of-custody event log, and statutory citations into a digitally signed, tamper-evident PDF forensic dossier satisfying Qanun-e-Shahadat Order 1984 (Art 164).

04 Mathematical & Algorithmic Formulations

4.1 Error Level Analysis (ELA) Physics

When a digital document containing raster elements is compressed with JPEG, the Discrete Cosine Transform (DCT) discards high-frequency visual components in 8x8 pixel blocks based on a quantization table $Q$. When an adversary pastes a new element (e.g. an altered number or stamp) onto an existing document and re-saves it, the newly pasted area undergoes its first compression pass, whereas the surrounding authentic background undergoes its second compression pass.

Error Level Analysis Difference Formulation
Let I(x, y) be the original 24-bit RGB pixel tensor, and J_Q(x, y) be the image resaved at quality Q = 95.
The raw error residual is: R(x, y) = | I(x, y) - J_Q(x, y) |
The normalized visual display tensor is: E(x, y) = min(255, R(x, y) * S)
where S is the scale factor (default S = 10). Tampered regions appear as bright, high-entropy clusters.

4.2 Typographic Baseline Displacement Linear Regression

In authentic bank statements generated by enterprise core banking software, text rows are laid out with mathematical precision along a continuous baseline. When text is inserted via consumer PDF editors, slight misalignment occurs between original and inserted glyphs.

Baseline Jitter & Alignment Regression
For a sequence of glyphs g_1, g_2, ... g_n along a horizontal text line with bottom coordinates y_i at horizontal positions x_i:
Fitted baseline: y = alpha * x + beta, where alpha, beta are derived via Ordinary Least Squares (OLS):
alpha = Cov(x, y) / Var(x)
Residual Jitter: epsilon_i = | y_i - (alpha * x_i + beta) |
If max(epsilon_i) > 1.2 pt or Var(epsilon) > 0.45 pt^2 ==> Spliced Typographic Anomaly Flagged.

4.3 Deterministic Lakh / Crore Balance Continuity

Pakistani financial statements utilize the South Asian numbering system (Lakh: $10^5$, Crore: $10^7$) with commas formatted as `1,00,000.00` and `1,00,00,000.00`, alongside standard Western formatting (`100,000.00`). DeepTrace’s parser normalizes these variations and verifies sequential zero-tolerance continuity.

Sequential Balance Equation (Strict Decimal Floating Invariant)
For transaction record t_k in chronological order k = 1, 2, ... N:
Expected_Balance_k = Balance_{k-1} + Credit_k - Debit_k
Discrepancy: Delta_k = | Reported_Balance_k - Expected_Balance_k |
If Delta_k > 0.009 PKR ==> CRITICAL FRAUD VIOLATION (Zero-Tolerance Deterministic Rule).

4.4 ISO 7064 MOD-97-10 PK-IBAN Validation

Pakistani IBANs comprise exactly 24 alphanumeric characters structured as: `PK` (Country Code, 2 chars) + `kk` (Check digits, 2 numeric) + `AAAA` (Bank Identifier, 4 alpha) + `16 alphanumeric account digits`.

ISO 7064 Check Digits Verification Algorithm
1. Rearrange characters: Move first 4 characters to the end: [Bank ID + Account] + "PK" + "kk"
2. Convert letters to integers: 'A' = 10, 'B' = 11, ... 'Z' = 35 ('P' = 25, 'K' = 20)
3. Compute large integer modulo: BigInt(Converted_String) mod 97 == 1
If remainder != 1 ==> Check digits are mathematically fabricated. Immediate HIGH Risk Flag.

4.5 Bayesian Evidence Fusion Model

Multi-Signal Bayesian Fusion for Composite Risk Score (0–100)
Let T be the hypothesis that the document is tampered, with prior P(T).
Given independent evidence signals E = {e_1, e_2, ... e_m} across deterministic, CV, and font engines:
P(T | E) = [ P(T) * Prod( P(e_j | T) ) ] / [ P(T) * Prod( P(e_j | T) ) + (1 - P(T)) * Prod( P(e_j | ~T) ) ]
Composite Risk Score = round( 100 * P(T | E) )
Override Clause: If any Deterministic Rule (Delta_k > 0 or MOD-97 failure) fires, Score = max(Score, 90).

05 Multi-Agent AI Swarm & LangGraph Orchestration

5.1 Swarm Architecture & Agent Specialization

To provide institutional banking analysts with comprehensive, natural-language forensic explanations without hallucination, DeepTrace employs a specialized Multi-Agent Swarm orchestrated using LangGraph. The swarm comprises four autonomous agents, each constrained to a distinct forensic domain.

Agent 1: Structural Inspector PDF Tree
Analyzes PDF object hierarchies, XRef tables, AcroForm annotations, incremental revisions, and metadata anomalies. Reports unflattened form fields, post-production stream edits, and Producer software signatures.
Agent 2: Computer Vision Inspector Pixel AI
Interprets ELA heatmaps, copy-move matching clusters, font baseline regression jitter, and glyph bounding box anomalies. Translates raw coordinate anomalies into human-readable visual evidence descriptions.
Agent 3: PK Regulatory Analyst Banking Rules
Evaluates Pakistani banking rules: PK-IBAN validity, FBR NTN format, 1LINK routing codes, Lakh/Crore balance math, and statutory compliance under SBP BPRD 05/2020, PECA 2016, and ETO 2002.
Agent 4: Lead Forensic Investigator (Synthesis & Verdict)
Synthesizes reports from Agents 1, 2, and 3. Reconciles conflicting signals, applies the Bayesian belief fusion weights, cross-checks findings against verified pipeline manifests, and generates the final executive verdict, risk score, and court-admissible summary.

5.2 The Zero-Hallucination Policy

In high-stakes banking and judicial environments, LLM hallucinations are catastrophic. DeepTrace solves this through a multi-tiered cryptographic ground-truth enforcement framework:

  • Ground-Truth Manifest Invariant: Agents are provided with a read-only, cryptographically verified JSON evidence manifest generated by deterministic stages 1–6.
  • Assertion Verification Filter: Before any agent turn is committed to the database or presented to the user, an automated validation layer verifies that every cited dollar/rupee amount, date, account number, or bounding box exists in the ground-truth manifest.
  • Negative Proof Directive: If an agent cannot verify a user question against the manifest, it is constrained by system instructions to state: "Inconclusive: Evidence manifest contains no empirical data supporting this inquiry."

6.2 Advanced Database Safeguards & Engine Extensions

07 Security Audit & Vulnerability Remediation

7.1 Comprehensive Security Review

During technical validation, a rigorous multi-vector security audit was conducted covering data-in-transit, data-at-rest, identity authorization, and database isolation. Five critical and high-severity vulnerabilities were identified and systematically remediated.

Vulnerability Description Severity Exploitation Mechanism Remediation Implementation
Multi-Tenant RLS Bypass via Superuser Connection CRITICAL Connecting via PostgreSQL `postgres` superuser bypassed all 19 RLS policies due to `rolbypassrls = true`, allowing cross-tenant data leakage. Created non-superuser role `deeptrace_app` with `NOSUPERUSER NOBYPASSRLS`. Granted only explicit table-level DML and verified cross-tenant query rejections empirically.
SQL Injection in RLS Context Setter HIGH Tenant variable was set via string formatting (`f"SET LOCAL app.current_org_id = '{org_id}'"`), susceptible to SQL injection. Enforced strict alphanumeric regex validation (`^[a-zA-Z0-9_\-]+$`) and converted to parameterized query: `SELECT set_config('app.current_org_id', $1, true)`.
Low-Entropy Administrative Credentials HIGH Default administrative `postgres` account was configured with dictionary password `12345`. Rotated administrative credentials to a 32-character high-entropy cryptographic secret. Verified dictionary rejection.
Non-Compliant Statement & Connection Audit Logging MEDIUM Database connection, disconnection, and DDL logging were disabled, violating SBP BPRD audit requirements. Applied engine parameters: `log_connections = on`, `log_disconnections = on`, `log_statement = 'ddl'`, `log_min_duration_statement = 1000`.
Unrestricted Network Interface Binding MEDIUM Database bound to `0.0.0.0:*`, exposing port 5432 to public subnet. Reconfigured `listen_addresses = 'localhost'` (internal loopback / Docker network only). Blocked external traffic.

7.2 Cryptographic Key Management & Secret Rotation

All sensitive operations adhere to NIST SP 800-57 guidelines:

By wedding deterministic mathematical rules with computer vision physics and multi-agent reasoning, it eliminates false positives while providing court-admissible certainty. Future enhancements include real-time Core Banking System (CBS) webhooks and a cross-bank shared fraud intelligence ledger.
